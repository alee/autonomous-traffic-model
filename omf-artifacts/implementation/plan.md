Version: 0.6 | Date: 2026-11-17 | Authority: OMFB | Status: initial Python package and engineering checks implemented

Authoritative inputs are ../abm-spec.md, ../conceptual-model.md, ../assumptions.md, ../phoenix-case-study.md, ../scenario-register.md, and ../experiment-plan.md. Preserve finite storage, persistent identities, constrained observations, original trip request times, and physical limits. Accepted hypothetical accounting profiles are externalized in scenarios/coronado-benchmark.json; unresolved physical profiles remain explicit.

Next implementation steps: resolve scientific input/profile definitions; complete the selected SUMO adapter and resolve the numerical clock without silently changing physics; implement recipe resolution and semantic checks; initialize environment/control state and occupancy-conditioned actors; generate stable exogenous realizations; implement complete checkpoint capture/restore at a declared schedule boundary; verify exact continuation before using checkpoints to accelerate experiments. FAIR owns release/environment stewardship; OMFA owns unresolved scientific defaults and any cross-policy checkpoint intervention.

Risks: incomplete snapshots, implicit defaults, population truth leaking into policy observations, shifted event/demand clocks, warmup observations dropped from accounting, policy-dependent random consumption, and transplanted controller state invalidating comparisons. Definitions and verification requirements are in parameter-schema.md and verification-plan.md. No Phoenix traffic outcomes or compatibility with untested platforms/models are claimed.

## Current implementation slice
src/autonomous_traffic/demand.py generates stable synthetic households, resident/external persons, prepositioned resident service vehicles and unrouted future requests. Named independent streams and integer-microsecond request times keep repeatable exogenous realizations separate from future policy draws. This numerical input representation still needs explicit alignment with an eventual engine clock. src/autonomous_traffic/sumo/probe.py is an engineering fixture, not a scientific traffic model. Four original generator tests plus six CLI tests passed. Next: acquire/audit the configured Coronado AOI and context; resolve origin/destination access, time-dependent lane/turn rules, initial on-road realization, controllers/dynamics and operator assignments; then connect the accepted demand to routes without dropping unrealized requests.
